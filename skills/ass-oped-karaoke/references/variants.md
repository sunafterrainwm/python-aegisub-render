# 衍生版：lite、NCOP／NCED、繁簡

三種衍生版都共用同一份歌詞、`\k` 與 Lua。差別分別在**模板清單**、**時間軸與 credit**、**語言標記**。
全部用 `scripts/variants.py`。

**先確認這個版本該不該做**（預設交付只有 OP／ED 的本篇完整版，而且不一定兩首都有）：

| 版本 | 觸發條件 |
| --- | --- |
| lite | **使用者抱怨太複雜／太吃效能**，要一個簡化版時才做。不要預先生成 |
| NCOP／NCED | **原始字幕本身就帶著曲名 credit** 時可以主動做（credit 總得有地方放）；否則等使用者指示 |
| 繁簡 | 這個流程本來就有繁簡轉換時 |

多一個版本就多一份要跟著改、跟著驗證、跟著回報的東西。

## lite 版

給播放器負擔較小的場合（也給「不想要滿畫面特效」的觀眾）。

**做法是換一張模板清單，不是複製一份程式碼。** 遞移裁剪會把沒用到的定義留在外面
（見 `lua-layout.md`），所以 lite 檔裡不會出現用不到的函式。

```bash
python -X utf8 scripts/variants.py lite op_kfx.ass -o op_kfx_lite.ass \
    --lua fx-build/lua_common.lua fx-build/lua_op.lua fx-build/lua_op_lite.lua \
    --templates fx-build/templates_op_lite.txt
```

典型的取捨（實際專案的結果）：

- 進退場：逐幀動畫 → 淡入淡出（必要時加一段位移），保留逐詞彈出的那幾個詞；
- 拿掉抖動、粒子、光暈層、場景光點、離場顆粒、塗鴉這類「每字好幾層」的裝飾；
- 逐幀輸出的動畫改成**分段線性**：位置走直線的一段合併成一個 `\move`，縮放／旋轉／透明度／顏色
  用 `\t`，只在曲線處切段；粒子數減半、路徑容差放寬。

量化目標：完整版 2.9 萬行／6.5 MB、同時最多 150 個事件 → lite 1.05 萬行／2.7 MB、
同時事件約 77 個。**同時事件數比總行數重要**，那才是播放器會卡的地方。

另一個會踩到的點：**lite 版的進場時間要和完整版一致**。逐詞進場的行要用
`L.start_time + (grp("seq") and basesyl.start_time or 0)`，不要一律用 `L.start_time`，
否則後半句會在行首就提前出現。

## NC 版（NCOP／NCED）

NC 影片沒有原本的 staff 文字，所以**曲名 credit 只放在 NC 版**，本篇的交付檔不放。

```bash
python -X utf8 scripts/variants.py nc op_kfx.ass -o op_ncop.ass \
    --shift -1678 --fps 24000/1001 \
    --video ncop.mp4 --title "<作品> - OP kfx (NCOP)" \
    --const OP_B0 --drop-fx
```

`--const` 後面是**你的 Lua 裡拍點原點那個常數真正的名字**（這裡的 `OP_B0` 是舉例；
不確定就看 `luasync.py extract` 出來的 Lua，或直接跑一次——名字對不到時 `variants.py`
會報錯並列出檔裡所有「名字 = 數字」的常數，不會寫出檔案）。

要做的事，一件都不能漏：

1. **每一行的時間平移到 NC 的時間軸**。用影格數（`--shift -1678 --fps …`，走
   `shift_time_by_frames`），或用時間戳（`--shift -0:03:03.97`）。
   影格數比較準：NC 第 0 格對應正片第幾格是用畫格比對出來的，用毫秒換算會差一格。
   **有歌詞行會落到 0 秒之前時 `variants.py` 會報錯不寫檔**：那代表位移的方向或數值不對，
   或這份字幕不在你以為的那條時間軸上（例如它其實已經是 NC 時間軸）。這時不要硬做，
   也不要加 `--allow-clamp` 交差——回頭確認字幕的時間，或把矛盾告訴使用者。
2. **code 行裡的拍點原點跟著平移**（`--const OP_B0`：把 `OP_B0=184010` 改成 `OP_B0=114023`，-1678 格＝-69987 ms）。
   漏掉這件事的症狀是「NC 版的特效和拍子差了三分鐘」。常數移動的是 N 格的標稱長度
   （不是某一行吸附到影格之後的差值），所以 +N 再 -N 會回到原值。
   代價是常數和各行實際移動的毫秒數會差幾 ms（每一行吸附到影格中點的量不同，沒有哪個單一數字
   能同時對上所有行）。離拍點判定門檻只有幾 ms 的音節因此可能在 NC 版換邊——平移之後拿
   `cmpfx.py` 和正片版比一次，有差異的行逐條看；那種差異是預期內的，回報時講明就好，
   不要為了讓它變成 0 去手調常數（調過的常數就回不到正片版的值了）。
3. **本篇專用的避讓要關掉**（`--set OP_FINAL_SHIFT=0`）：最後一句往旁邊閃是為了避開本篇片尾的
   製作／© 卡，NC 上沒有那張卡。
4. **換 Video File／Audio File／Title**（`--video`、`--title`）。
5. **加上曲名 credit 與它的載體行**。credit 的外觀照歌詞那一套（同一組配色、同一組描線動畫），
   不要照原版 credit 的「粗白邊＋模糊」；位置與內容照原版或量出來。
6. **丟掉舊的 fx 行**（`--drop-fx`），套模板時本來也會重建，但留著會讓檔案莫名變大。

### 亂數會變

如果亂數種子含行的開始時間，平移之後抖動角度、顆粒位置就和本篇不同。要兩版一致就把種子改成
「文本雜湊＋長度（格數）＋樣式＋字的位置」。改完之後 NC 版平移前後應該逐行相同，
**只有刻意不同的那幾行（例如 `OP_FINAL_SHIFT=0` 影響到的最後一句）才該有差異**——
拿 `cmpfx.py` 比一次就知道有沒有做到。

### 燒在 NC 上檢查不需要先產生 NC 版

```bash
python -X utf8 scripts/frames.py shot.png --ass op_kfx.ass --video ncop.mp4 \
    --shift -1678 --fps 24000/1001 -t 15 59
```

## 繁簡

搭配把繁體轉成簡體的流程（`convert_subtitles` 那一類）時：

- **Name 欄位保留 `+TC`／`+SC` 後綴**（`ED list+TC`），轉換腳本靠它分繁簡；
- 簡體行的 Effect 設成 `karaoke`，讓模板也處理它們；
- 繁體特效行是 Dialogue，簡體特效行輸出成 Comment（Aegisub 預覽時不疊字），轉簡時才升格；
- 套用模板後把來源行的後綴改成 `#TC`／`#SC`，避免已註解的原句被升格回 Dialogue；
- **繁簡的字不一樣寬**，所以模板要在繁簡轉換**之後**各自再套一次，不能套一次共用；
- **模板程式碼裡不要有任何中文字面值**（貨幣詞移到 `\-USD` 這種 inline fx，語言判斷用
  `line.style:sub(3) == "JP"` 這種布林值，不要用 `"CHT"` 字面值）。
  否則繁簡轉換會連程式碼一起改掉，判斷就壞了。
- **日中行一一對應是硬規矩**：同一句的日文行與中文行 `(Start, End, Name)` 必須一樣。
  對不上就是資料問題，不要放寬配對規則（例如改成比對時間重疊），那只是把錯蓋起來。

```bash
python -X utf8 scripts/variants.py lang x.ass --check     # 檢查 +TC/+SC 後綴與日中行配對
```
